# 备份恢复与用户删除重放

数据库恢复时，保留已删除身份的标记可以防止旧会话和私有数据重新出现。删除标记来自原服务在用户确认清除时提交的 `app_user` 墓碑。恢复操作使用同一环境的 `HMAC_KEY` 验证签名。

1. 在正常运行期间，将删除标记备份到独立受控位置，每次更新保存为新文件。保留包含最后一次已确认删除的权威状态或数据库变更日志，覆盖仍可能恢复的备份周期。清单只含不透明用户 ID 和删除时间，也需限制访问。
2. 恢复演练或切换前，停止应用对原库的写入。从最新权威状态导出删除标记，确认成功且覆盖停写时点。在 Windows PowerShell 中可以用 `qushuiyin-server.exe deletions export | Set-Content -Encoding ascii -LiteralPath <清单路径>`。如果最新权威状态不可用，先从保留的数据库变更日志恢复删除标记。
3. 将备份还原到隔离目标，迁移到当前版本，保持应用和后台入口离线。让 `MYSQL_DSN` 指向该目标并核对库名和地址。运行 `qushuiyin-server.exe deletions replay <清单路径>`。只有签名验证、全部标记处理和命令退出均成功后才开放入口。执行中断时使用同一清单重跑。
4. 抽检重放前的会话、结果、媒体票据、用户反馈和管理端反馈详情。命令在每位用户的事务中恢复删除标记，清除会话、媒体授权、结果、反馈、诊断等私有行。共享媒体保留给其他有有效引用的用户，失去授权引用的缓存文件由正常清理流程回收。备份和标记保存遵循相应保留策略。

A52 集成测试在隔离 MySQL 8.4 中先保存会话与工单的删除前行，执行正式删除接口，再模拟恢复这些行。验证错误签名无副作用、合法清单可重复重放、重放后旧会话和管理端工单不可访问。
