## 1. 文档约定与产品决策

### 1.1 规范用语

- 必须：首版验收要求。
- 建议：默认采用；改动需记录原因并同步相关章节。
- P0：首版必需；P1：稳定后补充；P2：另行规划。
- 解析成功：得到满足契约的媒体描述；不等于媒体下载或相册保存成功。
- 准备完成：该项已确定下载方式并完成对应校验（§13.7）。中转项为服务端已有通过验证的可分发文件；直连项为服务端已保存一个通过轻量探测、未过期的平台地址。不等于用户已保存。
- 下载完成：文件已完整到达客户端临时路径；不等于相册写入成功。
- 保存成功：客户端相册 API 成功回调。该回调只能作为客户端报告，服务端不能据此证明文件永久存在于相册。
- 源地址：平台返回的可能包含短期签名的 URL，默认只在服务端使用。例外只有三个出口，均只发给本人、每个地址对应一个资源、受频率限制，规则见 §13.7：直连下载地址、直连预览地址、复制链接。
- 媒体票据：本服务签发的短期访问凭证，与源地址分离。
- 直连下载：客户端直接从平台 CDN 下载文件，本服务只下发经过校验的平台下载地址，不承担文件流量。
- 中转下载：本服务先从平台取回并校验文件，再通过自有媒体域名提供给客户端。

### 1.2 首版固定决策

| 决策 | V1.1 采用方案 | 原因 |
| --- | --- | --- |
| 前端形态 | 微信原生小程序；组件和服务层分离 | 围绕相册、文件下载和生命周期直接开发 |
| 后端形态 | Go 单体业务服务，编译为单一可执行文件，逻辑分模块 | 内存占用低、启动快，并发和大文件传输性能好；配置、鉴权、状态与管理集中处理，部署只有一个文件 |
| 解析引擎 | [parse-video](https://github.com/wujunwei928/parse-video)（Go，MIT）以 Go module 直接引入业务服务，锁定版本，不改源码；不设独立解析服务 | 已覆盖目标平台视频与图集，出站边界经过安全加固；少一个进程和一次内网调用；上游更新只需升级版本号 |
| 运营后台 | 自研：业务服务内 `/admin/v1` 接口 + Vue 3 + Element Plus 管理端，构建产物嵌入 Go 程序一起发布 | 不额外部署前端服务；不使用解析库自带的演示页面和 HTTP 服务 |
| 任务运行 | MySQL 持久化任务 + 后端有界 worker 池/调度器 | 首版不依赖独立消息中间件，重启后可恢复状态 |
| 缓存与短期状态 | 首版单实例部署，不使用 Redis：会话、解析缓存、限流、熔断、传输租约、票据撤销放在进程内存且全部有上限；会话和每日额度计数持久化到 MySQL；文件字节放受控临时目录 | 参考机型 2 核 2 GB（§19.2）即可，少一个组件，读写更快；重启后会话仍有效。多实例部署前必须引入 Redis（P1，见 §15.6） |
| 下载方式 | 直连为主、中转为辅（§13.7）：地址落在已登记的 downloadFile 合法域名内时让客户端直连平台 CDN；不满足时先重新解析，仍不行再走有大小上限的中转；都不行时引导复制链接到浏览器下载 | 绝大部分文件流量走平台 CDN，小带宽服务器即可支撑；与现有去水印小程序的主流做法一致 |
| 媒体缓存 | 同一作品的同一资源跨用户共享一份已准备文件（仅中转下载）；授权和票据仍按用户 | 热门作品只从平台取回一次，减少源站流量、等待时间、磁盘占用和平台风控压力 |
| 用户身份 | 首次使用在线业务时通过 wx.login 建立业务会话 | 无账号密码、头像、昵称、手机号流程 |
| 历史记录 | 本机保存；服务端仅保留运行必需的短期任务数据 | 不建立云端作品收藏 |
| 广告/收费 | 首版关闭 | 先验证保存成功率和流量成本 |
| 导航 | 单首页，无底部 TabBar | 控制入口和页面层级 |
| 内容开放 | 平台和内容类型分别开关 | 视频可用不代表图集可用 |

若实际项目使用 uni-app，业务契约保持不变，但文件、权限、下载、后台恢复必须用最终微信产物真机验证。不得把 Web 页面可下载视为小程序可保存。

### 1.3 用户目标与完成定义

| 场景 | 用户目标 | 完成定义 |
| --- | --- | --- |
| 保存视频 | 拿到可播放视频 | 合法下载并收到相册成功回调 |

| 排查失败 | 知道为什么失败及下一步 | 具体提示、有限重试或反馈入口 |

## 2. 功能范围与能力矩阵

### 2.1 首版能力

首版覆盖：整段分享文本识别、自动平台识别、视频与静态图集、预览、视频/图片/封面保存、复制文案、本地记录、帮助、文字反馈、运营开关、错误诊断、限流和临时文件清理。

不覆盖：上传本地视频擦水印、批量粘贴多个作品、整主页采集、登录访问限制绕过、直播录制、会员/付费、背景音乐导出、实况照片完整保存、HLS/DASH 合并、视频全格式转码、云端收藏、跨设备同步。

“去水印”指链接解析取得可用媒体源，不保证移除视频画面本身的文字、字幕或作者标识。界面不使用“全网通用”“永久有效”“无限免费下载”等未经验证的承诺。

### 2.2 平台能力开放规则

| 平台 | 目标优先级 | 目标能力 | 初始上线状态 |
| --- | --- | --- | --- |
| 抖音 | P0 验证 | 视频、静态图集、封面、文案 | 全部待验证；逐项开放 |
| 小红书 | P0 验证 | 视频、静态图集、封面、文案 | 全部待验证；逐项开放 |
| 快手 | P0 验证 | 视频；图集按实测开放 | 全部待验证；逐项开放 |
| B站 | P0 验证 | 视频（首版为 html5 播放接口返回的单文件 MP4，清晰度受限）、封面、标题 | 全部待验证；逐项开放。高清（DASH 音视频分离 + FFmpeg 合并）为 P1 |
| 微博、头条、皮皮系列等 | P1 | 根据需求和可维护性评估；解析库已有对应解析器，开放前仍须实测 | 不展示为已支持 |
| 视频号及其他未核实平台 | P2/待研究 | 未确认 | 不支持，不从名称推断能力 |

每个平台配置：`status`、`videoEnabled`、`imageEnabled`、`coverEnabled`、`textEnabled`、`maintenanceMessage`、`adapterVersion`、`shareDomains`（允许的分享链接主机列表，§5.1）、`deliveryPolicy`（按内容类型 video/image/cover 分别设置，§13.7）。`status` 为 `enabled/maintenance/disabled`；只有 `enabled` 且具体能力为 true 才能开放对应操作。

`shareDomains` 的匹配规则与解析库一致：主机等于列表中的值，或以“.值”结尾（按 DNS 标签匹配，如 `m.bilibili.com` 匹配 `bilibili.com`）。初始值取自解析库锁定版本，升级解析库时核对：

| 平台 | platform | shareDomains 初始值 |
| --- | --- | --- |
| 抖音 | douyin | v.douyin.com、www.iesdouyin.com、www.douyin.com |
| 快手 | kuaishou | v.kuaishou.com、www.kuaishou.com |
| 小红书 | xiaohongshu | www.xiaohongshu.com、xhslink.com、xhslink.cn |
| B站 | bilibili | bilibili.com、b23.tv |

数据库迁移为这四个平台写入 platform_config 初始行：`status=disabled`，全部能力为 false，`adapter_name=parse-video`，`adapter_version` 为锁定提交号。开放哪个平台、哪种内容由负责人根据 M0 结果在管理端打开。

`deliveryPolicy` 初始值（M0 实测后由运营调整）：

| 平台 | video | image / cover |
| --- | --- | --- |
| 抖音、快手、小红书 | direct_preferred | direct_preferred（WebP 等需转换的图片自动走中转） |
| B站 | relay_only（CDN 校验 Referer，小程序无法设置该请求头；M0 验证直连可行后再改） | direct_preferred |

每项能力记录：样本日期、样本数、成功数、错误类型、解析器提交版本、测试环境、iOS/Android 客户端版本。真实成功率只能来自测试或运行数据。

### 2.3 未支持内容的处理

- 私密、删除、权限受限内容：无法区分具体原因时显示“作品无法访问，可能已删除或限制访问”，不虚构确定结论。
- 实况内容：只有适配器明确识别出静态图片，才可降级为静态图集，并显示“当前仅支持保存静态图片”；否则返回不支持。
- 混合媒体或多段视频：首版拒绝未定义的组合，不悄悄只保存第一段。
- B站多 P 视频：首版只支持第 1P。链接未带 `p` 参数或 `p=1` 时正常解析；指定其他分 P 时返回不支持，提示“当前仅支持第 1P”，不悄悄返回第 1P。短链接无法展开、因而无法确认分 P 时同样拒绝，不返回第 1P。番剧、课程、充电专属、大会员专享内容不支持。
- 超大图集：超过结果数量上限时明确报错，不静默截断；正常图集按批次选择保存。
- 无标题、无封面或无文案：使用对应占位/隐藏操作，不把缺少可选字段当解析失败。
- 核心视频地址为空、图集数组为空、结构错误：返回上游数据无效，不展示空成功页。

## 3. 页面结构与视觉交互规范

### 3.1 路由

| 路由 | 标题 | 入口与返回 |
| --- | --- | --- |
| `/pages/home/index` | 产品名 | 启动页 |
| `/pages/result/index?resultId=...` | 解析结果 | 首页或记录；返回保留本次输入 |
| `/pages/history/index` | 最近记录 | 首页；返回首页 |
| `/pages/help/index` | 使用帮助 | 首页/失败页 |
| `/pages/feedback/create?traceId=...` | 问题反馈 | 帮助/失败页 |
| `/pages/feedback/list` | 我的反馈 | 帮助 |
| `/pages/feedback/detail?id=...` | 反馈详情 | 我的反馈 |
| `/pages/privacy/index` | 数据与隐私 | 帮助/首页底部 |

页面参数只传不透明 ID，不传原分享文本、源地址、Cookie、签名媒体地址。进入结果页时必须重新校验本地会话和结果归属。

### 3.2 视觉原则

- 微信标准导航，适配安全区；白底、深色文字、一个品牌强调色。
- 首屏优先输入区与主按钮；支持平台用紧凑文字或图标，不为每个平台造独立入口。
- 一个视图只有一个最明显的主操作。视频为“保存视频”，图集为“保存选中图片”。
- 可点击区域建议不小于 44×44 逻辑像素；文字和状态不能只靠颜色区分。
- 长标题两行截断，可展开文案；图片按自身比例显示，不强行拉伸。
- 只在可测量的下载阶段展示百分比；未知总量时显示“正在下载”。
- 操作提示使用“解析中”“准备文件”“下载中”“保存到相册”等用户能理解的词。

## 4. 首页和输入处理

### 4.1 布局

从上到下：产品名称与一句用途说明、必要的平台维护提示、文本输入区、主操作、支持平台、三步教程、最近记录入口、帮助/数据与隐私入口。

维护提示只在影响当前能力时显示；可用平台列表来自配置，不写死为全平台支持。首次打开可完整浏览教程，不强制用户先建立会话。

### 4.2 输入与按钮

| 当前情况 | 主按钮 | 行为 |
| --- | --- | --- |
| 输入为空 | 粘贴并解析 | 用户点击后读取一次剪贴板，填入并开始校验 |
| 输入非空 | 开始解析 | 对当前输入校验，不重新读剪贴板 |
| 正在提交/解析 | 正在解析 | 防重复点击，可见取消操作 |
| 解析失败 | 重新解析 | 保留输入；按错误类型允许重试或编辑 |

输入区支持手动粘贴、换行、清空，默认最多 5000 个 Unicode 字符。服务端同时限制字符数和 HTTP 请求体大小；两端使用相同计数约定。剪贴板为空或读取失败时提示“请先复制作品分享链接”，并允许手动输入。

禁止在 `onLaunch/onShow` 中自动读取剪贴板。取消剪贴板或必要隐私授权后留在当前页面，不循环弹窗。

### 4.3 多链接

服务端从文本提取候选 URL 并去重：

- 0 个：`NO_LINK_FOUND`，提示输入链接。
- 1 个：继续识别平台。
- 多个：`MULTIPLE_LINKS`，返回最多 10 个候选；前端展示域名和截断路径供用户选择。
- 超过候选数量上限：提示只粘贴一个作品，不默认选第一条。
- 用户确认后重新提交原文本和 `selectedUrl`；服务端确认选择项属于本次候选。

多链接选择属于一个作品的选择流程，不是批量解析。

### 4.4 首页验收

F01—F04：空输入、带中文分享文案、前后空白、全角标点、多链接、超长文本、重复点击均有确定行为；维护状态在创建任务前与服务端执行前分别检查。

## 5. 链接识别与解析流程

### 5.1 服务端识别

1. 校验业务会话、输入大小、用户限流和全局可用性。
2. 提取 URL；处理外层引号和明显的句末分隔符，不随意裁剪路径或查询参数。
3. 用 URL 解析器获取协议、主机和端口。不得仅用“字符串包含 douyin”判定来源。
4. 仅允许平台配置 `shareDomains` 中的主机；拒绝用户信息段、字面 IP、非常规端口和非 HTTP(S) 协议。
5. 适配层用自有的受控解析器跟随短链接跳转（最多 `max_redirects` 次，每跳重新校验协议、主机和解析后的目标 IP，只读响应头不读正文），得到规范化作品链接，用于提取作品 ID（contentId）和判断 B站分 P 等规则（§2.3）。这一步失败不阻断解析，contentId 记为 null。例外：B站短链接（b23.tv）展开失败时无法确认用户要的是第几 P，不调用解析库，直接返回 `CONTENT_TYPE_UNSUPPORTED`（§2.3）。
6. 保留作品访问必需的签名参数，不能通用地删除所有 query。
7. 校验平台能力、幂等键与缓存；创建或复用本用户的解析任务。
8. 把**用户原始分享链接**（而非第 5 步的规范化链接）交给解析库（§12.1），规范化返回结构，验证核心字段，再发布结果。解析库内部有自己的跳转与出站限制，与第 5 步互不替代。

HTTP 分享链接仅对已验证平台升级到 HTTPS；升级不可用时按平台适配规则处理，不对任意 HTTP 地址开放抓取。

### 5.2 用户等待

- 创建任务返回 `202` 后每 2 秒查询一次；客户端最多自动等待 40 秒。
- 服务端单次解析任务总预算 25 秒，包含排队、调用和内部重试。
- 接近前端等待上限仍无结果时，显示“暂时没有取得结果，可稍后重试”，保留任务编号和输入。
- 用户取消后停止客户端轮询，并请求取消任务；后端不能立即中断的调用也不得把迟到结果推到已取消页面。
- 返回首页后可重新发起；不得由旧回调覆盖新请求的结果。

### 5.3 缓存和重试

- 解析缓存跨用户共享（§15.6），只存规范化解析结果，不含用户信息；键为平台、`sourceHash`、适配器版本、凭证配置版本。`sourceHash` = HMAC(服务端密钥, 链接)：§5.1 第 5 步成功时用规范化作品链接，失败时用用户原始分享链接。每个用户命中缓存后仍得到自己的 resultId。
- 元数据缓存默认 5 分钟；上游有更短期限时取更短值并预留时钟余量。
- 缓存命中仍检查平台开关与资源归属。
- 首版不做解析库调用的内部重试（`parser_transient_retries` 为 0）：解析库返回的是不分类型的文本错误，无法可靠识别“短暂错误”。用户可手动重试。
- 删除、无权限、参数无效、不支持格式等不自动重试。
- 源失效后的刷新由媒体准备模块控制，单个保存批次最多触发一次共享刷新。
- 用户主动重新解析可用 `forceRefresh=true` 跳过解析缓存；新结果成功后替换共享缓存中的同键条目。仍受限流和幂等约束。

## 6. 视频结果、预览和保存

### 6.1 展示

顺序：来源平台、视频封面/播放器、标题、时长与文件信息（已知才显示）、主按钮“保存视频”、次要操作“保存封面/复制文案”、继续解析、问题反馈。

标题为空显示“未命名作品”；时长、分辨率、大小未知时不显示虚假值。不得将未验证的清晰度标为“原画/4K”。`authorName` 为可选文字信息，首版不必加载作者头像。

### 6.2 预览

- 初次进入只展示封面，不自动请求完整视频或播放。
- 用户点击播放后申请预览地址，再设置播放器地址。
- 预览地址由 `preview-tickets` 接口逐项发放（§14.6），服务端按 §13.7 第 1–3 步为该资源单独判定：可直连时返回校验过的平台地址，不占用本服务流量；否则返回本服务的受控预览地址（有限 Range，受 `preview_max_bytes` 限制）。播放器组件能否播放第三方地址须在 M0 真机验证，验证前直连预览默认关闭（配置 `direct_preview_enabled`）。源要求不满足时明确提示无法预览。
- 播放失败显示“预览暂不可用，可尝试保存”；只有服务端确认媒体不可用时才禁用保存。
- 视频预览流量与文件保存流量分别统计，取消播放及时释放连接。
- 预览地址过期时最多刷新一次；资源本身失效则提示重新解析。

预览不作为下载可用性的证明，下载前仍必须完成 §13.7 的下载方式判定与对应校验。

### 6.3 保存操作

1. 用户点击“保存视频”，为本次操作生成一个 `clientActionId` 和幂等键。
2. 检查当前微信隐私要求及相册写入授权；拒绝则停止，不先消耗大文件流量。
3. 调用创建保存批次接口，只有一个视频 `assetId`。
4. 查询批次，等待该项准备完成；显示“正在准备文件”。直连项的准备只是地址校验，通常很快；中转项需要服务端取回文件。
5. 申请下载地址：直连项得到平台 CDN 地址，中转项得到自有域名签名地址（§14.9）。调用 `wx.downloadFile`，监听真实下载进度。直连下载被拒或内容异常（域名不在合法列表、403、非媒体内容等）时，调用回退接口（§14.9）切换下载方式，不直接报失败。
6. 检查 HTTP 状态、文件非空、预期大小等客户端可验证信息；服务端返回的 JSON 错误不得送入相册 API。直连项另按 §13.7“直连项的内容校验”在客户端补做检查。
7. 调用 `wx.saveVideoToPhotosAlbum`；成功后才显示“已保存到相册”。
8. 更新本地结果并上报阶段事件；统计上报失败不得把成功提示改成失败。
9. 清理客户端临时文件；前台仍需要预览或重试的路径保留到释放引用时再删。

主按钮状态：保存视频 → 准备文件 → 下载中 → 保存中 → 已保存。完成后允许用户明确选择“再次保存”；该动作会创建新操作，不自动重复写相册。

### 6.4 限制与异常

- 首版选择通过兼容验证的 MP4；MP4 扩展名不代表编码必然兼容。
- 目标编码建议 H.264 视频及 AAC 音频；无音轨的视频可允许，具体容器/编码组合在真机能力表中确认。
- 不通过修改扩展名把 HLS、DASH、HTML 或其他内容伪装成 MP4。
- 文件超限：准备阶段终止，显示实际可知大小和业务上限；未知大小在传输累计到上限时中止。
- 下载失败而临时文件不完整：删除临时文件，用户重试时重新下载。
- 相册保存失败但临时文件完整：优先复用该临时文件重试，不再次拉取视频。
- 用户取消：停止网络任务和未执行的相册动作；已经写入相册的文件不会被自动删除。
- 页面离开或客户端进程结束：不承诺后台下载，不显示假完成。

## 7. 图集、封面和文案

### 7.1 图集展示与选择

- 图片按作品原始顺序排列，显示序号、缩略图和勾选状态；图片 ID 稳定且唯一。
- 点击图片主体预览，点击勾选区域改变选择，避免预览与选择互相触发。
- 首次默认选中前 `max_image_batch_count` 张；图片总数更多时明确提示需要分批保存。
- “全选”只在总数不超过批次上限时可直接使用；否则提供“选择前 20 张”等与实际配置一致的操作。
- 主按钮显示“保存选中图片（N）”；N=0 时禁用并说明需要选择。
- 解析结果最多 100 张；超过时返回 `TOO_MANY_ASSETS`，不静默丢弃。
- 缩略图和大图预览地址按需逐项申请（§14.6 preview-tickets，滚动到可见区域时才申请），不在结果查询时一次签发；加载失败不移除该图片和序号。

### 7.2 批量保存

- 一个点击创建一个保存批次，记录不可变的图片 ID 和顺序快照。
- 后端按最多 2 个媒体工作线程准备文件；前端按顺序逐张下载和写相册，默认并发 1。
- 相册授权检查一次；处理中用户改变系统权限时暂停剩余项目并展示恢复操作。
- 有些图片失败时继续其他可执行项；网络整体离线、授权拒绝、磁盘不足等全局问题应暂停。
- 进度至少显示“已保存 S/N 张”；单项下载进度可显示，但不能用图片序号伪造字节进度。
- 完成汇总分别列出成功、失败、未完成；“取消”不等同失败。
- 仅重试失败/未完成项；本批次已收到成功回调的项不再次写入。
- 再次保存一整套属于新操作，可能在用户相册生成重复文件，界面应由用户明确触发。

无法控制不同设备相册最终排序，因此承诺按原顺序发起保存，不承诺系统相册一定保持同样排序。

### 7.3 图片格式

- JPEG/PNG 在通过类型、大小、像素数量检查后优先原文件分发。
- WebP 首版需要受控转换：普通图片转 JPEG；有透明通道时转 PNG；转换后标记 `converted=true`。
- 动态 WebP/动图首版不自动当作静态原图；若提供首帧保存，必须作为另行开放能力并明确说明，V1.0 默认拒绝。
- HEIC、AVIF、GIF 动图等未验证格式返回 `FORMAT_UNSUPPORTED`，不承诺全格式保存。
- 转换只解决相册兼容性，不进行画面水印擦除；不声称转换后的文件与原文件字节一致。
- 图片解码必须限制像素总量和内存；拒绝恶意或损坏文件，见媒体模块约束。

### 7.4 封面保存

有独立 `role=cover` 的图片资源才显示按钮，复用单图片保存批次。封面源失效可单独失败，不改变已经成功的视频结果。若只有首张图可预览，不得未经说明把它命名为平台独立封面。

### 7.5 复制文案

采用 `description` 字段；没有 description 但有真实 title 时可复制 title。两者皆空则隐藏按钮。保留换行与文本内容，不加入推广尾巴、不复制分享口令；操作成功后短提示“文案已复制”。

## 8. 最近记录与本地数据

### 8.1 记录时机与字段

默认在解析成功后写入最近记录，失败不写普通列表。记录最多 100 条，30 天自动过期，最近操作置顶。

字段：`schemaVersion/localId/userId/platform/contentId/sourceUrl/title/mediaType/assetCount/parsedAt/lastUsedAt/lastSaveSummary/thumbnailLocalPath`。`sourceUrl` 是重新解析需要的作品分享链接，不是媒体直链；必要的签名参数必须保留。

- 去重优先 `(userId, platform, contentId)`；缺少 contentId 时用规范化分享链接摘要。
- 重复解析更新原记录的时间和内容，不重复插入。
- 只存一张小尺寸本机缩略图；不可长期使用过期的签名地址作为历史封面。
- 不存视频文件、完整图集、Cookie、短期媒体票据或后台密钥。
- 本地缩略图总预算默认 10 MiB，按最近使用清理；缺图用平台占位图。

### 8.2 打开历史

历史按业务用户 ID 分区。本次启动尚未确认当前身份前，不展示上次用户的记录；离线且不能确认身份时提示联网后查看。

点开记录时，仍有效的本用户结果可复用；否则使用 sourceUrl 重新解析。不得用过期的源直链直接恢复。源分享链接也可能失效，应提示重新从原平台复制。

展示“最近一次报告保存成功”等历史结果时，不暗示文件现在一定还在相册。

### 8.3 删除、清空和关闭

- 单条删除直接执行，可短暂提供撤销；删除其专属缩略图。
- 清空全部记录需要一次确认，说明不删除系统相册文件。
- 关闭“记录最近解析”后不写新记录；已存在记录由用户选择保留或清空。
- “清理本机缓存”清理临时媒体和缩略图；历史文字记录是否删除要单列选项。
- 本地配额写满时降级为不记录，不能阻断已成功的解析和保存。
- 数据结构升级保留 `schemaVersion`；迁移失败仅清理本应用对应键，不清空其他不相关数据。

## 9. 帮助、反馈与隐私页面

### 9.1 帮助

至少覆盖：如何复制分享链接、支持平台和类型、为什么预览失败、为什么保存失败、如何开启相册权限、图集分批保存、链接过期、超大文件、历史保留规则、数据清理方式。

平台教程只说明用户在原平台的正常分享操作，不引导提取他人凭证或绕过访问限制。教程和支持范围可由配置更新；内容以纯文本或受控 Markdown 渲染，不加载任意脚本。

### 9.2 提交反馈

字段：问题类型（解析失败/下载失败/相册失败/图集问题/建议/其他）、描述（5—500 字）、可选联系方式（最多 100 字）、可选 traceId、可选作品链接。

traceId 只在归属当前用户或不含用户数据的公共错误时接受。作品链接默认不附带，用户勾选“附带本次作品链接，便于排查”后才提交；字段下方说明该链接可能含访问参数。

V1.0 不支持截图上传，避免为反馈引入文件上传链路。联系方式不强制填写；提交成功显示工单编号和“查看反馈”，不承诺具体回复时限。

### 9.3 反馈列表与详情

状态：`pending` 待处理、`processing` 处理中、`replied` 已回复、`closed` 已关闭。

列表显示类型、描述摘要、状态、提交时间。详情采用统一工单面板，上半反馈内容，下半处理结果，显示提交和最近回复时间。首版不做聊天气泡、实时聊天或消息推送；运营多次修改回复以最新结果展示，后台保存审计。

用户只能看自己的工单。返回列表时刷新该条状态；工单失效或被清理显示“该反馈已不存在”。

### 9.4 数据与隐私

页面包含：实际服务用途、隐私保护指引入口、用户协议、相册/剪贴板用途说明、本地记录开关、本机缓存清理、服务端数据清理、反馈入口。

“清除本机数据”与“清除服务端数据”分开操作，说明范围。服务器短期解析处理意味着不能写“所有数据只存在本机”。说明应准确表达“最近记录保存在本机，解析所需信息会发送至服务器处理”。

服务端数据清理删除或作不可逆去标识处理：当前用户的会话、作品结果、源链接、临时媒体引用、反馈及联系方式、可关联的明细事件。汇总统计不含可回溯用户的标识，可继续保留；备份按周期到期，恢复备份后必须重放删除记录。

## 10. 会话、权限和小程序生命周期

### 10.1 业务会话

- 首页配置和帮助可匿名获取。
- 首次解析、查看本人记录/反馈等操作需要业务身份；先满足当期平台隐私要求，再调用 `wx.login` 获取 code。
- 业务后端用 code 调用微信登录凭证校验接口，获取 OpenID 并建立本应用用户标识。
- 建议用 `HMAC(serverKey, appId + openId)` 作为内部稳定查找键，返回另行生成的 userId。
- AppSecret 和 session_key 不下发；本项目不依赖微信数据解密时，不长期保存 session_key。
- 自定义 token 使用高熵随机值，服务端只存摘要，默认 24 小时绝对过期；客户端请求放在 Authorization 头。
- 401 时集中单飞刷新会话，最多自动重试原请求一次；创建任务时复用原幂等键，避免登录恢复制造重复任务。
- 不把客户端提交的 userId/openId 当作身份证明，不接受前端指定别人身份。

wx.login 的身份建立、平台隐私授权、相册权限是不同步骤，不以其中一个成功代替其他步骤。

### 10.2 隐私与相册授权

隐私 API 和具体需声明接口名单以当前微信官方文档与小程序后台为准，开发时统一封装 `ensurePrivacyFor(action)`，使用当前支持的隐私设置查询、必要时授权及隐私协议查看能力；不自造一个勾选框代替微信要求。

相册保存前查询相关设置，需要时在用户操作下申请 `scope.writePhotosAlbum`。已拒绝时通过说明按钮引导用户主动打开设置；系统层权限拒绝与小程序层授权分开解释。用户拒绝后不循环调用授权接口。

不申请摄像头、麦克风、通讯录、位置、手机号等与首版无关的权限。复制文案、读取剪贴板等按当前接口要求声明和触发。

### 10.3 生命周期与恢复

| 事件 | 必须处理 |
| --- | --- |
| 页面隐藏/onHide | 停止轮询和新相册动作；中止客户端下载并标记未完成；服务器有限准备任务可继续 |
| 回到前台/onShow | 检查网络/会话，查询原任务；用户点击继续后恢复未完成保存 |
| 返回上一页 | 若有保存任务，询问是否离开；确认后停止本页面回调和下载 |
| 系统中断/进程结束 | 下次启动只恢复操作摘要；不自动重新写相册 |
| 登录身份变化 | 隔离旧用户任务和本地记录，不展示旧记录 |
| 弱网或离线 | 保留输入，停止无效重试，给用户明确重试入口 |

客户端为每次页面任务保存 generation 标识，所有异步回调必须匹配当前 generation 才能更新界面。

相册 API 已发起后可能不能取消。若进程在“写入成功但尚未记录回调”之间结束，将该项标为 `UNKNOWN` 并提示“保存结果未确认，重试可能产生重复图片”，不得承诺跨进程绝对不重复。

## 11. 状态模型与幂等规则

### 11.1 解析任务

| 状态 | 含义 | 允许下一状态 |
| --- | --- | --- |
| QUEUED | 已入持久化任务队列 | RUNNING、FAILED、CANCELLED |
| RUNNING | 已被工作线程领取 | SUCCEEDED、FAILED、CANCELLED |
| SUCCEEDED | 规范化成功且结果已发布 | 终态 |
| FAILED | 失败，带稳定业务错误码 | 终态 |
| CANCELLED | 用户取消或被管理操作终止 | 终态 |

解析超时为 `FAILED + PARSE_TIMEOUT`。客户端停止等待不直接等于服务端失败。取消与成功竞争通过版本号条件更新解决；成功先提交则取消接口返回当前 SUCCEEDED，取消先提交则迟到结果丢弃且不创建可访问授权。

任务保留期到期后查询返回 `410 JOB_EXPIRED`；成功任务对应结果先到期时，任务仍可查询，但获取结果返回 `410 RESULT_EXPIRED`。

### 11.2 服务端保存批次

批次状态用于“准备文件”，不包含相册是否成功。

| 状态 | 判定 |
| --- | --- |
| PREPARING | 仍有待准备或准备中的项 |
| READY | 所有项当前均可下载（中转项有可用文件，直连项有未过期的已校验地址） |
| PARTIAL_READY | 没有待处理项，至少一项 READY 且有失败/过期/取消项 |
| FAILED | 无可用文件，至少一项失败，无待处理项 |
| CANCELLED | 用户明确取消整个批次，或所有项均已取消；保留逐项已完成信息 |
| EXPIRED | 无可用文件，至少一项过期，其余只可能是过期/取消项 |

单项准备状态：`PENDING/PREPARING/READY/FAILED/CANCELLED/EXPIRED`。中转项 READY 对应不可变媒体对象，直连项 READY 对应一个已校验的平台地址（`direct_expires_at` 前有效）。只能复制链接的项为 FAILED，错误码为 `DIRECT_DOWNLOAD_UNAVAILABLE` 或 `FILE_TOO_LARGE`，并带 `copyLinkAvailable=true`；它在聚合时按 FAILED 计。媒体或直连地址到期后变为 EXPIRED；重试时增加 attempt 并回到 PENDING。整个批次过期则返回 410，需要新建批次或重新解析。

聚合判定顺序固定为：整体取消或全项取消 → CANCELLED；否则有待处理项 → PREPARING；否则全项 READY → READY；否则有 READY → PARTIAL_READY；否则有 FAILED → FAILED；否则为 EXPIRED。重试只能改变符合条件的项，不改变客户端已保存成功记录。

### 11.3 客户端单项保存

| 状态 | 含义及恢复 |
| --- | --- |
| WAITING | 等待服务端完成该项准备（中转文件或直连地址校验） |
| DOWNLOADING | 正在下载，可中止 |
| DOWNLOADED | 完整临时文件可复用 |
| SAVING | 正在调用相册 API |
| SUCCEEDED | 收到相册成功回调 |
| FAILED | 明确失败，记录发生阶段和错误 |
| CANCELLED | 尚未完成即被用户取消 |
| UNKNOWN | 相册操作结果无法确认；重试前提示重复风险 |

系统层授权问题使用 FAILED 的错误分类并暂停队列，不额外把“无权限”混成文件失效。

### 11.4 幂等与去重

创建解析任务、保存批次、重试批次、直连回退（`routeOperation=save_item_fallback`）、提交反馈都必须带 `Idempotency-Key`（客户端生成随机 UUID）。同 key 重放回退请求返回首次的响应，不会因“已回退过”而报错。下载地址、预览地址、复制链接接口只读取或签发地址，不需要幂等键。

- 唯一作用域为 `(userId, routeOperation, key)`，默认保留 24 小时。
- 相同 key、相同请求内容：返回原对象，不重复创建；首次 202 的异步接口重放时可仍返回 202 和同一 ID。
- 相同 key、不同请求内容：`409 IDEMPOTENCY_CONFLICT`。
- 请求摘要使用规范化内容的 HMAC；不把分享文本或隐私信息放入普通去重日志。
- 一次网络重试复用 key；用户新的一次明确操作使用新 key。
- 如果原对象已过期，返回明确过期错误，不能同 key 悄悄创建另一任务。
- 相同内容可共享有效的解析缓存（跨用户，见 §15.6），并发到达的相同内容只调用一次解析库；但每个逻辑任务仍记录自己的 traceId，每个用户得到自己的 resultId。

### 11.5 可靠执行

任务先落库再返回。工作线程采用原子领取、`version/leaseOwner/leaseExpiresAt` 和递增领取序号；发布结果必须匹配领取序号，旧线程不得覆盖新线程。

服务重启后扫描超时租约：仍在总预算内可重新领取，否则落为失败。取消标志和总截止时间在领取、调用返回、写结果三处检查。数据库事务内提交对象与幂等记录，避免“已创建任务但没有幂等记录”的重复窗口。

## 12. 解析器接入与统一模型

### 12.1 解析库选型与接入规则

解析使用 [parse-video](https://github.com/wujunwei928/parse-video) 的 Go 库（包 `github.com/wujunwei928/parse-video/parser`），以 Go module 依赖直接编译进业务服务，**不修改其源码**，不设独立解析服务。V1.0 原定的 PHP 仓库 jiuhunwl/short_videos、V1.1 草案中的 Python 版 parse-video-py 均不采用。

分工：

- 业务服务自研：会话、任务、限流、平台开关、媒体准备与票据、反馈、运营后台。
- 解析库只做一件事：输入分享链接，输出作品描述。它的结果只在业务服务的解析适配层内使用，适配层负责转换为 §12.3 模型和稳定错误码。

接入规则：

1. `go.mod` 锁定到上游提交 `00e8e11`（2026-11-08），版本记录在发布包中。上游要求 Go 工具链 ≥ 1.26.10。
2. 升级上游 = 修改锁定版本 + 跑全部平台样本回归，通过后发布；不让生产自动跟随上游 main。
3. 只调用 `parser` 包的 `ParseVideoShareUrlContext(ctx, url)`，传入带任务截止时间的 `ctx`；不使用上游的 `cmd` 包（Gin HTTP 服务、CLI、下载功能）。
4. 上游的出站边界位于库内部，随调用自动生效：平台域名白名单逐跳校验、在连接层拒绝私网和特殊用途 IP、跨主机重定向剥离凭证、响应 16 MiB 上限、单次解析 30 秒超时、最多 10 次重定向。适配层不得绕过或放宽。
5. 适配层先按 §5.1 规则自行判定平台，只把已开放平台的链接交给解析库；未开放平台直接返回不支持。
6. 上游返回的错误大多是普通文本错误，没有类型区分。适配层只依据可判定的条件映射 §18 错误码，原始错误文本只进服务端日志（脱敏后），不返回客户端：
   - 链接不属于任何已开放平台（适配层自行判定，不调用解析库）→ `PLATFORM_UNSUPPORTED` 或 `LINK_NOT_ALLOWED`；
   - `ctx` 超过任务截止时间 → `PARSE_TIMEOUT`；`ctx` 因用户取消而结束 → 任务 `CANCELLED`；
   - 解析库返回错误（其余所有情况）→ `UPSTREAM_UNAVAILABLE`。这类错误可能来自平台故障，也可能是链接失效或作品已删除，因此 `retryable=true` 但客户端不自动重试，只提示用户可手动重试一次或检查链接；在熔断中单独计数（§16.4 `circuit_library_error_percent`），不与超时和无效响应混算；
   - 解析库未返回错误，但 `VideoUrl` 与 `Images` 均为空、或媒体地址既不是 HTTPS 也不是可升级的 HTTP 地址 → `UPSTREAM_INVALID_RESPONSE`（HTTP 地址的处理见 §12.4）。B 站可选封面按 §12.4 单独降级。
   首版无法区分“作品已删除/受限”，`CONTENT_UNAVAILABLE` 仅供将来的自研适配器使用。
7. 不设置上游的 `PARSE_VIDEO_DOUYIN_COOKIE` 环境变量。首版**禁止使用任何登录账号的 Cookie**；只允许平台自身页面在同一次解析过程中下发的匿名会话 Cookie（例如抖音分享页下发的会话），这类 Cookie 只在该次请求的内存中使用，不持久化、不跨用户复用、不记录日志。
8. 上游某平台失效且尚未修复时：优先向上游提交修复。确需先上线时，在适配层为该平台换用自研实现（上游内部解析器不对外公开，无法单独覆盖），登记在案，上游修复并升级后删除。禁止 fork 或 `replace` 指向修改过的上游代码，也不得直接复制未审查的第三方修复代码；自研实现须自行编写并有测试。

   **当前登记的自研替代（2026-11-19）：抖音（视频与图集）。** 原因：抖音分享页不再内嵌作品数据，锁定版本的解析库改为必须提供 Cookie（上游 issue #110，修复 PR #102/#106/#108 均未合并）。替代做法（思路参考上游 PR #106，MIT；代码自研）：
   - 跟随短链得到作品 ID（§5.1 第 5 步）；无法得到作品 ID 时返回 `UPSTREAM_UNAVAILABLE`。
   - 以 iPhone Safari 的 User-Agent（与解析库默认值 `parser.DefaultUserAgent` 一致）请求 `https://www.iesdouyin.com/share/video/{作品ID}/`。实测（2026-11-19）：iPhone UA 24/24 成功；Android UA 16 次中 4 次返回的 webId 不足 16 字节导致失败。xsstoken 缺失或 webId 不足 16 字节时，重新请求一次分享页再试，仍不满足则返回 `UPSTREAM_UNAVAILABLE`。读取页面中 `id=douyin_reflow_token` 元素的 `xsstoken` 属性、`id=douyin_reflow_webId` 元素的 `webId` 与 `usercip` 属性（属性值可能不带引号），保留该页面下发的会话 Cookie。
   - `reflow_id` = Base64(AES-128-CBC(xsstoken，PKCS#7 填充，密钥与 IV 均为 webId 的前 16 字节))。
   - 请求 `https://www.iesdouyin.com/web/api/v2/aweme/iteminfo/`，参数 `reflow_source=reflow_page`、`web_id`、`device_id`（均为 webId）、`use_new_select_scope=0`、`item_ids`、`reflow_id`，有 usercip 时带 `user_cip`；带分享页 Referer 与会话 Cookie。要求 HTTP 200、`status_code=0`、`item_list[0].aweme_id` 等于作品 ID。
   - 映射：`desc` → title 与 description；`video.play_addr.url_list[0]`（`playwm` 替换为 `play`）→ 视频；`video.cover.url_list[0]` → 封面；`images[]` 非空 → 图集。每张图的 `url_list` 通常含多个地址（实测 2026-11-19：前 3 个为 WebP、第 4 个为 JPEG，均可访问）：优先取路径扩展名为 `.jpeg`/`.jpg` 的地址，没有则取 `url_list[0]`（WebP 按 §7.3 走中转转换）；其余地址作为同一张图的备用候选，不另算资源。实测图片主机为 `p3/p5/p9/p11/p26-sign.douyinpic.com` 等，iteminfo 接口已返回图集，无需 `a_bogus`。
   - 出站请求沿用 §5.1 与 §13.2 的逐跳校验和私网拦截，仅访问 `douyin.com`、`iesdouyin.com`、`snssdk.com` 及其子域；媒体地址跳转后的主机按 §13.7 登记与判定。
   - 实测（2026-11-19，Windows，3 条公开视频）：3/3 成功，媒体探测均为 206 video/mp4。最终 CDN 主机有一部分是 `*.douyinvod.com`，也有随机生成的主机（如 `<数字>.qrstuvwxyzab.com`），后者无法预先登记，按 §13.7 走中转。
   - 平台风控（实测 2026-11-19）：同一 IP 在约 10 分钟内发出上百次分享页请求后，抖音对该 IP 返回 HTTP 200 的验证页（不含 xsstoken/webId，含 captcha 脚本），持续时间未知，任何客户端都会失败。因此：分享页连续两次缺少 xsstoken 或 webId 时，判为“平台验证页”，返回 `UPSTREAM_UNAVAILABLE`，并计入该平台的验证页计数（§16.4 `upstream_challenge_threshold`）；对平台的出站请求受 `upstream_requests_per_minute` 限制。规则见下文“平台出站频率保护”。
   - 上游合并修复并通过样本回归后删除本替代，恢复调用解析库。
9. 每个平台建立一组适配器测试样本；只有映射和媒体准备均通过才开放能力。
10. 发布物中保留上游 MIT 版权和许可声明。

上游返回字段（`VideoParseInfo`）与 §12.3 的对应（字段不足的部分按允许为空处理）：

| 上游字段 | 映射 |
| --- | --- |
| `VideoUrl` / `Images[]` | `Images` 非空为 image，否则为 video；图片按原顺序编号 |
| `Images[].LivePhotoUrl` | 首版不使用，按 §2.3 降级为静态图并加 warning |
| `CoverUrl` | `cover`；为空时隐藏封面保存；B 站非 HTTPS 封面按 §12.4 处理 |
| `Title` | 上游不区分标题与文案，同时作为 `title` 与 `description` |
| `Author.Name` | `authorName` |
| `MusicUrl` | 首版不使用 |
| 无 | `contentId` 由适配层从 §5.1 第 5 步得到的规范化作品链接提取，提取不到为 null；`durationMs` 为 null |

检查到的上游事实（锁定提交，未部署实测）：

- 抖音：锁定版本的解析库已失效（需要 Cookie），首版改用自研替代，见本节第 8 条。视频地址把 `playwm` 替换为 `play` 属于 §12.4 允许的“经验证的平台规则”。
- B站调用 html5 播放接口，取得音视频合一的 MP4，无需 FFmpeg；只取第 1P，未登录时清晰度受限。
- 图集实况图在 Go 版中只有小红书提供，首版统一降级为静态图，不受影响。

这些事实必须通过适配器统一，不能让小程序直接绑定解析库的原始结构。来源见第 23 章。

### 12.2 适配器职责

逻辑接口：`match(url) / resolve(ctx, shareUrl) / normalize(info) / classifyError(err)`。首版每个平台的 `resolve` 都调用解析库 `ParseVideoShareUrlContext`，`normalize` 处理其返回的 `VideoParseInfo`，`classifyError` 按 §12.1 第 6 条映射。

每个适配器负责：分享域名识别（§5.1）、短链接规范化与 contentId 提取、必要查询参数保留、视频/图集判定、媒体地址提取、错误归类。解析库调用成功与必需字段可用必须分别检查。§12.1 第 8 条的自研替代实现也必须实现同一接口，对业务层透明。

前端永远不知道所用解析库、平台 Cookie 和备用媒体源顺序。来源切换通过业务接口保持稳定，首版每个平台只需一个已验证来源。

### 12.3 统一结果模型

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| resultId | string | 不透明 ID，本用户可访问 |
| platform | string | douyin/xiaohongshu/kuaishou/bilibili；新平台用配置注册 |
| contentId | string/null | 平台作品 ID；大数字保留字符串 |
| mediaType | enum | video/image；V1.0 不向前端暴露未知混合类型 |
| title | string/null | 原作品标题，不填 HTML |
| description | string/null | 原作品文案，可含换行 |
| authorName | string/null | 可选；不作为用户身份 |
| durationMs | integer/null | 明确统一为毫秒，不依据数字大小猜单位 |
| assetCount | integer | 视频为 1，图集为正文图片数，封面不计入 |
| assets | Asset[] | 正文媒体有序数组 |
| cover | Asset/null | 独立封面资源 |
| warnings | string[] | 例如 LIVE_PHOTO_AS_STATIC |
| createdAt / expiresAt | string | RFC 3339 UTC 时间 |
| capabilities | object | canPreview/canSave/canSaveCover/canCopyText |

Asset 字段：`assetId/type/role/order/mimeType/width/height/sizeBytes/converted/previewUrl/previewExpiresAt/availability/reasonCode`。type 为 video/image；role 为 content/cover；order 从 1 开始。mimeType、尺寸和字节数在未验证时可为 null。availability 为 candidate/ready/unavailable；candidate 只表示存在候选源，不承诺可保存。

源地址、备用源、所需请求头、源期限、Cookie 引用、校验摘要只在服务端内部模型保存。公开 API 不返回完整上游响应；源地址只能经 §13.7 列出的三个出口逐项发给本人，结果和批次查询中不出现。Asset 的 `previewUrl/previewExpiresAt` 在结果查询中恒为 null，预览地址通过 preview-tickets 单独申请。

### 12.4 字段映射与降级

以下规则针对解析库返回的 `VideoParseInfo`（字段对应见 §12.1）；自研替代实现须给出同样的规范化结果。

| 情况 | 适配规则 |
| --- | --- |
| `Images` 非空且 `VideoUrl` 也非空 | 按图集处理，`VideoUrl` 不作为正文资源（图文作品是否同时带视频地址待 M0 实测确认） |
| `Images` 为空，`VideoUrl` 非空 | 视频结果，assetCount=1 |
| 媒体地址为 `http://` | 改写为 `https://`（主机、路径、查询参数不变）后继续，由 §13.7 的轻量探测验证可访问；探测失败按不可下载处理，不改用 HTTP，也不把 HTTP 地址发给客户端。实测：小红书图片与视频 CDN 返回 http 地址，改为 https 后可正常访问 |
| 两者均为空，或地址不是合法的 HTTP(S) URL | `UPSTREAM_INVALID_RESPONSE`，不发布结果 |
| `Images` 数量超过 `max_result_assets` | `TOO_MANY_ASSETS`，不静默截断 |
| 某张图片带 `LivePhotoUrl` | 只保存静态图，结果加 warning `LIVE_PHOTO_AS_STATIC` |
| `CoverUrl` 为空 | 正常结果，隐藏封面保存 |
| B 站 `CoverUrl` 不符合 HTTPS 要求 | 合法正文继续返回；仅对下述已验证的 B 站封面地址尝试升级，不能验证的封面按缺失处理 |
| `Title` 为空 | title 与 description 为 null，界面显示“未命名作品”并隐藏复制文案 |
| 时长 | 解析库不提供，`durationMs` 为 null |

每个资源首版只有一个候选地址（解析库只返回一个）。`max_media_candidates` 只对将来能提供多个候选的自研适配器生效。

不得通用地修改媒体 URL 字符串来“去水印”；只有经验证的适配器规则可以生成特定平台媒体候选。

**P0：B 站封面 HTTPS 升级。** 仅对来自解析库的 `http://i2.hdslb.com/bfs/archive/` 封面地址，无用户信息或显式端口时，将协议改为 HTTPS，保留原路径及查询参数。服务端在解析预算内用 HEAD 探测，逐跳限制为同一 HTTPS 主机及路径前缀，并按 §13.2 校验 DNS 和连接 IP。仅当响应为 200、MIME 为 JPEG/PNG/WebP 且已知大小在 §16.3 图片限额内时保留封面候选；否则隐藏封面操作，合法视频正常返回。不对正文媒体或其他平台地址应用此规则，候选仍须经过 §13 的媒体准备与域名登记检查。

## 13. 媒体准备、缓存与下载

### 13.1 模块边界

业务 API 返回媒体 ID；媒体模块根据服务端已登记的候选源决定下载方式（§13.7）。用户不能提交任意 URL 给下载服务。小程序只访问已登记在小程序后台的域名：自有 API 域名、自有中转媒体域名，以及已登记的平台 CDN 域名。

中转下载必须实际提供文件字节。直连下载只下发已经在服务端跟随完跳转、最终主机已登记的地址，不能假定一个 302 到未登记域名的链接可以在客户端成功下载，也不能假定它已经解决签名或防盗链问题。源端确需请求头时由对应适配器的受控配置提供，客户端不能任意注入。

### 13.2 文件准备步骤

1. 校验批次/资源归属、类型、当前平台开关和限额。
2. 按共享键查找有效的已准备文件（规则见本节末）；命中则只为当前用户新建授权记录，跳过第 3–7 步。若同一共享键正在准备，等待该次准备结果，不重复取回。
3. 对候选源进行 HTTPS、域名、DNS/IP、重定向逐跳检查。唯一例外是本地开发的媒体 Mock（《03》§3.5），只在 `APP_ENV=local` 且 `PARSE_MODE=mock` 时生效，生产启动时拒绝该配置。
4. 可用 HEAD 辅助判断大小，但不把 HEAD 成功或失败当作最终依据；实际 GET 验证 MIME、文件头和累计字节数。
5. 写入随机命名 `.part` 文件；下载未完整结束时禁止被媒体域名访问。
6. 完整后探测容器/编码或图片格式、尺寸；必要时完成允许的 WebP 转换。
7. 计算输出文件 SHA-256、真实大小，原子改名，登记不可变的 media_file。
8. 为当前用户创建 media_object（授权），更新该项为 READY；票据只签给该 media_object，并只指向该不可变文件和版本。

工具调用禁止拼接用户内容进 shell，媒体探测/图片转换限制 CPU、内存、像素和执行时间，使用无特权进程。首版大文件输出由有界媒体模块承担，不占用普通接口的处理能力。

跨用户共享规则：

- 已准备文件（media_file）与用户授权（media_object）分离。文件字节只存一份；每个用户各有自己的 media_object，票据只签给 media_object，每次请求照常检查该用户的授权状态（§13.4）。
- 共享键 = 服务端 HMAC(平台, 作品 ID, 资源角色, 序号, 输出版本)。作品 ID 由适配层取得；取不到作品 ID 时该资源不共享，按单用户文件处理。共享键不含用户信息，也不拼接源地址。
- 只共享已通过第 4–7 步校验的 ready 文件；准备失败、校验失败的结果不共享，不能让一个用户的失败影响其他用户。
- 平台或适配器版本变化、源刷新后作品 ID 或图片对应关系变化时，产生新的输出版本，不复用旧文件。
- 共享只发生在服务端存储层。用户之间互相不可见：不能通过共享得知其他用户是否下载过同一作品，统计和日志也不记录这种关联。

### 13.3 源地址失效和切换

- 在文件准备完成前，可有限尝试已登记备用源。
- 明确源过期且作品结果仍有效时，批次共享一次重新解析；多个失败项不能各自刷新造成请求放大。
- 重新解析后校验作品 ID 和图片对应关系。图片无法稳定对应时返回 `CONTENT_CHANGED`，要求用户查看新结果，不能按旧序号保存别的图片。
- 一个 `.part` 文件只对应一个源响应；切源必须删除旧部分并重新开始，不能拼接不同实体。
- 已经签发的媒体对象字节不可变化；资源刷新产生新对象和新 ETag。

### 13.4 媒体票据和 Range

签名内容至少覆盖：媒体对象或预览资源 ID、用途（download/preview/thumbnail/image）、对象版本、过期时间、票据 ID。密钥只在服务端；票据默认为短期 bearer 凭证，因此日志必须脱敏 URL 查询参数。每次媒体请求还要检查对象授权未撤销及其所属用户未被删除，不能只验证签名后跳过当前授权状态。

- 下载票据默认 5 分钟，在每个请求开始时校验；已开始的合法传输不因途中到期强制断开。
- 允许受控的 GET/HEAD 和单段 Range，支持 200/206、Content-Length、Content-Type、Accept-Ranges、ETag；非法范围返回 416。
- Range 只能针对同一不可变文件。客户端首版不实现跨进程断点续传；该支持主要用于预览和网络层兼容。
- 不能做“一次 GET 即销毁”的票据，否则 HEAD、重试、Range 会互相冲突；按票据限制并发和累计字节数。
- 到期票据可在当前会话下重新申请；没有业务会话不能靠旧票据无限续期。
- 媒体访问错误在尚未发送文件头前返回带 requestId 的 JSON；传输中失败只能终止连接并在服务端记录，客户端按下载失败处理。

流量计量采用原子预留与结算：已知完整文件/Range 按预计响应字节预留，未知大小按有界块预留，发送后用实际字节结算并释放未使用预留。取消、断开、超时都执行结算；单用户与全局预算同时检查，不能因并发请求各自读到旧余额而大幅超限。HEAD 计请求频率但不当作完整文件下载计费。

### 13.5 预览与缩略图

视频点击预览才建立受控源连接，限制 Range、总字节（`preview_max_bytes`）和连接数；不为预览承诺完整可保存。

图片与封面的缩略图按需生成，不在解析时预取：

- 客户端在图片进入可见区域时，通过 preview-tickets 一次申请最多 `max_image_batch_count` 个资源的预览地址。
- 服务端对每个资源按 §13.7 第 1–3 步判定（预览不做“直连重新解析”）：可直连且 `direct_preview_enabled` 时返回平台地址，不消耗本服务资源；否则返回本服务缩略图地址。
- 预览与缩略图票据签给“资源 + 用途”（§13.4），授权依据是该资源所属结果属于本人且未过期，不创建 media_object。
- 本服务缩略图在首次被请求时生成，排队等待超过 `thumbnail_generate_timeout_seconds` 时返回 503 `SERVICE_BUSY`，客户端显示占位：取回原图（受 `max_image_bytes`、`max_image_pixels` 限制），等比缩放到最长边 `thumbnail_max_edge_px`，输出 JPEG（质量 `thumbnail_jpeg_quality`），由 `image_convert_workers` 限制并发。生成结果作为 media_file 跨用户共享（输出版本为 `thumb-{边长}`），占用 `media_cache_budget_bytes`。
- 大图预览使用 `/media/image/{assetId}`：输出原图（WebP 输出转换后的 JPEG/PNG），同样受 `max_image_bytes`、`max_image_pixels` 和出站额度限制。
- 失败时显示占位，不影响保存。

缩略图与中转预览的流量计入用户与全局出站额度，不因它不是正式下载就绕过限制。

### 13.6 缓存清理

每个用户授权（media_object）默认自创建起保留 15 分钟；共享文件（media_file）的有效期取引用它的所有有效授权中最晚的到期时间，新用户命中时随之延长，但单个文件自准备完成起不超过 24 小时，到期后重新取回，避免长期使用可能已失效的内容。结果/保存批次默认 30 分钟。票据有效期取“配置期限、授权剩余期、文件剩余可用期、批次/结果剩余有效期”的最小值，不签发比底层对象活得更久的票据。

活动传输持有有界租约；GC 不删除有效租约文件。租约随传输心跳续期，异常断开后有 60 秒清理宽限，不因永久残留锁无限保留。清理每 `media_gc_interval_seconds` 扫描一次过期文件和过期 `.part` 文件；磁盘压力下只淘汰未被使用的文件，并把关联 READY 状态更新为 EXPIRED。

用户删除数据时立即撤销该用户的全部授权和票据、停止未完成任务。共享文件只在没有任何有效授权引用、且没有活动传输时才删除物理字节；删除一个用户不影响其他用户正在使用的同一文件。已下载到用户相册的文件不由服务器删除。

### 13.7 下载方式：直连为主、中转为辅

微信小程序的 `wx.downloadFile` 只能访问在小程序后台登记过的“downloadFile 合法域名”。每类域名最多 200 个，必须写到具体主机名，不支持通配符；开发工具里关闭校验后能下载，不代表正式版可用。平台 CDN 的主机名数量多且会变化（经验数据：抖音超过 80 个）。全部走中转需要服务端承担所有文件流量，在小带宽服务器上大文件会很慢甚至失败。因此首版采用以下顺序为每个保存项决定下载方式。

**决定顺序**（服务端在准备阶段执行，客户端不能自选）：

1. 读取平台配置中该内容类型的 `deliveryPolicy`（§2.2）：`direct_preferred`、`relay_only`（例如需要特定请求头或防盗链的平台）、`copy_only`（只提供复制链接：仍执行第 2 步的跳转跟随与校验以得到最终地址，但不做直连判定，直接进入第 5 步）。
2. `direct_preferred` 时，服务端跟随源地址的全部跳转（仍按 §13.2 第 3 步逐跳校验），得到最终地址。最终主机在下载域名登记表（§15.5 download_domain）中为 `registered`，且地址不需要 Cookie 或自定义请求头，则进入第 3 步。否则记录该主机（新主机记为 `observed`），并按“直连重新解析”规则争取拿到已登记主机。
3. 对最终地址做一次轻量探测：优先 HEAD；平台不支持 HEAD 时用 `Range: bytes=0-{direct_probe_range_bytes - 1}`。要求状态码为 200/206、Content-Type 与资源类型一致（video/* 或 image/jpeg、image/png）、已知大小不超过 `max_video_bytes`（图片按 `max_image_bytes`）、剩余有效期满足下载窗口（见“直连地址有效期”）。Content-Type 为 `application/octet-stream`、`binary/octet-stream` 或缺失时，改用 Range 请求读取文件开头字节按魔数识别（JPEG `FF D8 FF`、PNG `89 50 4E 47`、WebP `RIFF....WEBP`、MP4 第 4–7 字节 `ftyp`），识别结果代替 Content-Type 参与判断；识别不出则视为不一致（实测：小红书封面返回 `application/octet-stream`）。通过则该项为 **direct**，状态 READY，地址加密保存（§15.4）。
4. 第 2、3 步不能满足，或图片需要格式转换（§7.3）时：若策略不是 `copy_only`，且已知或探测到的大小不超过 `relay_max_video_bytes`（图片按 `max_image_bytes`），该项为 **relay**，按 §13.2 准备文件。大小未知时按中转准备，在累计字节超过上限时中止并转入第 5 步。
5. 都不满足时，该项为 FAILED：超过 `max_video_bytes` 的错误码为 `FILE_TOO_LARGE`，其余为 `DIRECT_DOWNLOAD_UNAVAILABLE`。若第 2 步得到的最终地址不需要 Cookie 或自定义请求头且尚未过期，把它加密保存到 direct_url_enc、按“直连地址有效期”规则写入 direct_expires_at，并标记 `copyLinkAvailable=true`，结果页提供“复制下载链接，到浏览器下载”；否则只显示失败原因。

**直连重新解析**：每个批次最多 `direct_reparse_attempts` 次，由批次内所有因主机未登记而无法直连的项共享，不按项累计。重新解析跳过解析缓存，占用 `parser_workers`，不计入用户解析限流。新结果必须通过 §13.3 的同一资源校验（作品 ID、图片数量与顺序一致），否则按 `CONTENT_CHANGED` 处理。新结果替换共享解析缓存中的同键条目。

**直连地址有效期**：能从地址中可靠读出过期时间时（由各平台适配器按已验证的规则解析），`direct_expires_at` 取该时间减去 `ticket_safety_margin_seconds`；读不出时取探测时间加 `direct_url_assumed_ttl_seconds`。剩余有效期必须至少为 `client_download_timeout_seconds + ticket_safety_margin_seconds`，否则视为不可直连。到期后该项变为 EXPIRED，可通过重试重新判定下载方式。

**直连项的内容校验**：服务端只做了轻量探测，以下检查由客户端补做，任一不满足即视为直连失败并调用回退接口：

- `wx.downloadFile` 返回的 statusCode 为 200，临时文件非空；
- 下载过程中通过进度回调监控已下载字节，超过 `max_video_bytes`（图片 `max_image_bytes`）立即中止；
- 已知大小时，实际大小与探测值一致；
- 相册 API 因文件格式错误而失败时，视为内容异常，不重复写入，走回退。

**客户端回退**：直连失败（域名不在合法列表、403、上述内容校验不通过）时，客户端调用 `POST /v1/save-batches/{batchId}/items/{itemId}/fallback`，原因为 `DIRECT_DOWNLOAD_REJECTED` 或 `DIRECT_CONTENT_INVALID`（§14.9）。服务端按第 4、5 步改走中转或复制链接；同一项只允许回退一次，回退触发的中转准备计为该项一次准备尝试。

**下载域名登记**：

- 服务端把遇到的每个平台 CDN 主机记入 download_domain（只存主机名，不存路径和签名）。管理端“下载域名”页按平台列出 `observed` 主机及出现次数，运营在微信后台添加后标记为 `registered`；只有 `registered` 主机会被用于直连和直连预览。
- 状态：`observed`（已发现，未登记）、`registered`（已在微信后台登记，可直连）、`review`（直连失败率异常，暂停直连，待人工复核）、`ignored`（人工决定不登记）。
- 单个客户端的回退不会改变主机状态。服务端按主机累计直连回退次数：在 `direct_host_review_window_seconds` 内回退次数不少于 `direct_host_review_min_failures`，且回退占该主机直连下发次数的比例不低于 `direct_host_review_failure_percent` 时，自动从 `registered` 改为 `review` 并告警。由管理员复核后改回 `registered` 或改为 `ignored`。
- 合法域名名额（每类 200 个）同时要容纳自有中转媒体域名，按平台出现频率优先登记。
- 未登记主机占比或直连回退率超过阈值时告警（§18.4），提示补登记。

**安全与隐私边界**：源地址发给客户端只有三个出口，范围严格限定：

| 出口 | 接口 | 条件 |
| --- | --- | --- |
| 直连下载地址 | §14.9 tickets（deliveryMode=direct） | 该项为 direct 且未过期 |
| 直连预览地址 | §14.6 preview-tickets | 主机为 registered、探测通过且 `direct_preview_enabled` |
| 复制链接 | §14.9 copy-link | 该项 FAILED 且 `copyLinkAvailable=true` |

- 三个出口都只发给本人；每个地址对应一个资源，单次请求最多 `max_image_batch_count` 个；受频率限制（§16.4），每次发放记录服务端事件（不含地址本身）。
- 地址不出现在结果查询、批次查询、页面参数、本机历史、事件上报和普通日志中。
- 只发放不需要 Cookie、账号凭证或自定义请求头的地址；需要这些的资源只能中转。首版不使用平台账号 Cookie。
- 服务端仍不接受用户提交的任意地址；中转只处理服务端自己解析出的候选源。

**计量**：直连下载和直连预览不计入本服务出站流量额度（§16.4 的 egress 额度只计中转与本服务预览、缩略图），但地址申请受频率限制。直连占比、未登记主机占比、直连回退率单独统计（§18.3）。

## 14. HTTP API 开发契约

本章是本项目拟定的业务接口，不是开源仓库现有接口。示例 ID、URL、令牌均为占位样例，不能直接调用。

### 14.1 通用约定

- 前缀 `/v1`；管理接口 `/admin/v1`；普通接口使用 JSON UTF-8。
- 受保护接口使用 `Authorization: Bearer <token>`；不在 URL 放业务 token。
- 时间全部返回 RFC 3339 UTC，UI 按设备时区展示；运营日统计时区固定 Asia/Shanghai。
- 所有 ID 使用字符串；大小单位 byte，时长毫秒，比例为 0—100，未知值为 null。
- 成功响应 `code=OK`；错误使用稳定英文 code 和可展示的中文 message，不直接返回程序堆栈或上游原始错误。
- `requestId` 由服务端生成并贯穿日志；客户端可传单独的 `X-Client-Request-Id`，但不能覆盖服务端标识。
- 列表采用游标分页，默认 20、最多 50；游标必须绑定用户和过滤条件，不能伪造越权。

成功包络：

```json
{
  "code": "OK",
  "message": "成功",
  "requestId": "req_demo_01",
  "data": {}
}
```

错误包络：

```json
{
  "code": "RATE_LIMITED",
  "message": "操作较频繁，请稍后再试",
  "requestId": "req_demo_02",
  "data": null,
  "error": {
    "retryable": true,
    "retryAfterSeconds": 30,
    "details": {}
  }
}
```

注意：查询一个 FAILED 的异步任务，HTTP 仍可为 200、包络仍为 OK，因为查询本身成功；失败原因位于 `data.error`。媒体文件接口直接返回字节，不使用 JSON 成功包络。

### 14.2 接口清单

| 方法与路径 | 鉴权 | 用途 |

| GET `/v1/results/{resultId}` | 是 | 获取解析结果 |
| POST `/v1/results/{resultId}/preview-tickets` | 是 | 为视频或一组图片申请短期预览/缩略图地址（直连或本服务） |

### 14.3 配置与会话

`POST /v1/sessions/wechat` 请求：

### 14.5 查询/取消任务

### 14.9 票据、重试与取消

`POST /v1/save-batches/{batchId}/tickets` 请求 `{itemIds:[...]}`，200 返回 `tickets:[{itemId,deliveryMode,url,expiresAt}]`。只处理本人 READY 项；任一项不满足时返回明确错误，不偷偷创建新准备任务。relay 项的 url 是自有域名签名地址，expiresAt 遵循 §13.4；direct 项的 url 是 §13.7 保存的已校验平台地址，expiresAt 为 `direct_expires_at`。剩余期限不足以完成下载时把该项标记为 EXPIRED，由客户端请求 retry。受 `user_download_url_requests_per_minute` 限制。

`POST /v1/save-batches/{batchId}/items/{itemId}/fallback` 请求 `{reason}`，需要新幂等键。`reason` 取值：`DIRECT_DOWNLOAD_REJECTED`（下载被拒：域名不在合法列表、403、网络层拒绝）或 `DIRECT_CONTENT_INVALID`（客户端内容校验不通过，§13.7）。只接受本人、`deliveryMode=direct`、尚未回退过的项（READY 或 EXPIRED 均可）。服务端将该项置为 PREPARING，attempt 加一，按 §13.7 第 4、5 步重新判定；回退计入主机回退统计。回退不受 `media_prepare_max_attempts_per_item` 限制（避免已达上限的项无路可走）。项不存在或不属于本人返回 404 `RESOURCE_NOT_FOUND`；项不是 direct 或已经回退过返回 409 `FALLBACK_NOT_ALLOWED`。

`POST /v1/save-batches/{batchId}/items/{itemId}/copy-link` 无请求体。只接受本人、FAILED 且 `copyLinkAvailable=true` 的项；200 返回 `{url,expiresAt}`：url 为 direct_url_enc 中保存的最终平台地址，expiresAt 为 direct_expires_at；已过期返回 410 `MEDIA_SOURCE_EXPIRED`，客户端可对该项请求 retry 重新判定。受 `user_copy_link_per_day` 与 `user_download_url_requests_per_minute` 限制。客户端只把地址写入剪贴板并提示“链接很快会失效”，不显示在页面上、不写入本机历史。

`POST /v1/save-batches/{batchId}/retry` 请求 `{itemIds:[...]}`，需要新幂等键。允许可重试错误对应的 FAILED、EXPIRED 或单项 CANCELLED；永久格式错误等不自动重试。单项在同批次最多准备 `media_prepare_max_attempts_per_item` 次（含首次，回退也计入次数但不受此上限阻止），超出返回 RETRY_LIMIT_REACHED。批次整体已取消或有效期已过则要求新建；仅聚合状态为 EXPIRED 但批次本身仍在有效期内时允许重试。重试会重新执行 §13.7 的下载方式判定。

接受重试时，指定项 attempt 加一，新的准备 deadline 设为 `min(当前时间 + 批次准备预算, 批次 expiresAt)`，不能沿用已经过去的准备截止时间。仍需满足剩余期限足够完成准备与下载的校验。单批次累计源刷新次数不重置。

relay 项客户端只是下载失败（网络中断等）时刷新票据即可；direct 项下载被拒或内容异常时走 fallback，单纯网络中断可在 `direct_expires_at` 前直接重试同一地址。相册失败优先复用本地文件。若 result 已到期则必须重新解析，不能在 retry 内无限延长结果寿命。

`DELETE /v1/save-batches/{batchId}`：取消未完成准备、撤销后续票据；已经开始且无法中断的处理在完成时丢弃授权。不会删除用户已保存的相册内容，也不会把客户端 SUCCEEDED 改写成未保存。

### 14.10 事件上报

`POST /v1/events` 接受 `{events:[...]}`，每批最多 20 条。每条字段为 `eventId/name/flowId/clientActionId/jobId/batchId/itemId/deliveryMode/stage/outcome/errorCode/durationMs/bytes/clientTime/clientVersion/osFamily`，不适用字段为 null。`deliveryMode` 为 direct/relay/null。

200 返回 `{acceptedEventIds,duplicateEventIds,rejected:[{eventId,code}]}`。eventId 去重；用户对象归属逐条验证；不认识的事件类型拒绝。客户端统计队列最多 100 条、保留 24 小时，失败退避重传，不阻断用户操作。

客户端按当前确认的业务身份补传，在离线或后台暂停发送。收到逐条回执后移除已接收、重复和明确拒绝的条目。网络失败沿用原 eventId，按 §16 的初始和最大间隔做倍增退避。清除服务端数据成功后移除该身份的待传事件。

禁止上报作品文案、原链接、剪贴板全文、源地址、精确设备指纹、相册路径或 Cookie。客户端 bytes/duration 只能作体验参考，计费与限流用服务端计量。

### 14.11 反馈

POST 请求字段：`category/content/contact/traceId/includeSource/sourceUrl`。`category` 取值：`parse_failed`（解析失败）、`download_failed`（下载失败）、`album_failed`（相册失败）、`gallery_issue`（图集问题）、`suggestion`（建议）、`other`（其他）。includeSource=false 时拒绝非空 sourceUrl；联系信息和链接按敏感数据处理。支持的问题类型和字数限制见第 9 章。201 返回 `{feedbackId,status,createdAt}`。

列表请求 `?cursor=...&limit=20`；返回 `{items,nextCursor,hasMore}`，items 仅含 id/category/summary/status/createdAt/updatedAt。详情返回完整本人内容、脱敏联系方式和最新 reply/repliedAt；不返回完整调试日志或解析源凭证。

### 14.12 清理数据

`DELETE /v1/me/data` 在用户明确确认后调用。事务中设置用户删除标记、禁用对象访问并撤销会话；删除/去标识敏感数据，物理媒体清理由队列继续完成。

200 返回 `{accessRevoked:true,cleanupStatus:"scheduled",cleanupDeadlineAt:"..."}`，界面显示“已停止访问，相关数据将在 24 小时内清理”，不得写成所有物理副本已即时删除。调用返回后清理本机本用户 token 和业务数据；下次使用会重新建立最小服务身份。

服务端维护删除审计和重试清理，保证 24 小时内完成在线副本处理；备份默认最长 7 天滚动到期。清理失败触发内部告警，不静默丢弃任务。已撤销 token 的重复调用返回 401，客户端不为了重放清理请求自动重新登录。

## 15. 数据模型与存储设计

### 15.1 基础约定

以下为逻辑表设计，可据此编写数据库迁移。业务服务使用 MySQL，字段 snake_case；API 转为 camelCase。

- 主键 `id VARCHAR(64)`，由服务端生成随机不透明 ID；不把自增数据库行号作为授权依据。
- 共用字段 `created_at DATETIME(3)`、`updated_at DATETIME(3)`；状态修改表增加 `version INT UNSIGNED`。
- 所有时间按 UTC 存储；金额首版不存在。字节数使用 BIGINT UNSIGNED，时长使用非负整数。
- 字符集 utf8mb4；状态值由应用枚举校验，数据库约束与迁移保持一致。
- `user_id/result_id/batch_id` 等关联字段必须有索引；普通读写始终附加 user_id 条件。
- 任务状态、对象写入和幂等占位在同一事务提交；跨媒体字节操作用状态和补偿清理处理。
- 敏感字段使用带认证的加密方案，保存 `key_version`，密钥不放同一数据库。
- JSON 仅用于不稳定元数据和配置，不用一个大 JSON 代替需筛选的状态、用户和期限字段。

字段类型省略时遵循：`*_id/lease_owner` 为 VARCHAR(64)，`*_at/source_expires_at/deadline_at/expires_at` 为 DATETIME(3)，`*_version/adapter_version` 为 VARCHAR(100)（名为 version 的乐观锁字段除外），计数为 INT UNSIGNED，claim_seq 为 BIGINT UNSIGNED。尚未开始/完成的时间、未领取的租约和未产生的关联结果允许 NULL；用户归属、当前状态、创建时间、必需截止时间不得为空。迁移脚本必须将这些规则写成明确列定义，不依赖数据库隐式转换。

过期清理后如需返回准确的 410，保留最多 `tombstone_retention_days` 天的最小墓碑记录（对象 ID、归属、类型、过期时间，不含作品内容或源地址）；未找到墓碑或不属于当前用户则统一返回 404。用户主动清理数据时墓碑也撤销访问，不因错误提示便利继续暴露原对象。

### 15.6 进程内短期状态

首版单实例部署，不使用 Redis。以下状态保存在业务服务进程内存，每类都有数量上限（§16.3），按期限过期清理。

| 状态 | 键 | 内容 | 期限来源 | 重启后 |
| --- | --- | --- | --- | --- |
| 会话缓存 | tokenDigest | userId/过期时间/会话版本 | 会话 TTL | 丢失；按需从 app_session 重新加载，用户无感 |
| 解析缓存 | platform:sourceHash:adapterVersion:credentialVersion | 规范化解析结果（跨用户共享，不含用户 ID） | 解析缓存 TTL，不超过结果期限 | 丢失；重新调用解析库 |
| 进行中解析 | 同上 | 正在执行的解析调用，用于合并并发的相同请求 | 调用结束 | 丢失；任务按 §11.5 恢复 |
| 限流计数 | scope:subjectHash:window | 计数/令牌桶 | 对应限流窗口 | 分钟级窗口重新计数；每日额度从 usage_counter 恢复 |
| 熔断 | platform:adapterVersion | 熔断状态和样本计数 | 熔断窗口 | 恢复为关闭状态，按新样本重新判定 |
| 传输租约 | mediaFileId:connectionId | 活动传输租约 | 有界心跳续期 | 在途连接已断开，租约随之失效 |
| 票据撤销 | ticketId | 撤销标记 | 票据剩余有效期 | 丢失；由每次请求检查授权状态兜底 |
| 直连回退统计 | host:window | 窗口内直连下发次数与回退次数（§13.7） | `direct_host_review_window_seconds` | 丢失；累计总数在 download_domain 中，窗口重新计数 |

规则：

- 每日额度计数（§16.4）在内存中原子累加，每 `usage_flush_seconds` 写回 usage_counter，启动时读回。写回间隔内的计数可能在异常退出时丢失，属于可接受的有界误差。
- 内存上限触发时，先淘汰已过期条目，再按最近最少使用淘汰缓存类条目（会话缓存、解析缓存）。限流计数不得因容量被清空：容量不足时，对新出现的主体按保守限流处理，并记录告警。
- 键和日志不拼接原始链接、OpenID、Cookie 或联系方式。
- 多实例部署前，必须把会话缓存、解析缓存、限流、熔断、租约和票据撤销迁移到 Redis 等共享存储（P1）；在此之前不得水平扩容到多个实例。

active save batch 指尚在有效操作窗口且未取消/结束的逻辑保存操作，不能只看 PREPARING：READY 后仍可能在客户端下载。该操作占位使用 `save_batch_activity_lease_seconds` 活动租约，本人查询批次或申请票据时可续期，但不超过批次 expiresAt。客户端上报 save_action_finished 或用户取消时可释放；失去活动后最多一个租约期释放，避免用户被旧操作永久锁住。服务器媒体并发仍按真实连接/任务限制，不能只相信客户端结束事件。

管理端修改配置时的校验：整数不得为负；时长、数量、字节类键必须大于 0（`parser_transient_retries`、`direct_reparse_attempts` 可为 0）；百分比在 0–100；布尔值只能是 true/false；新值须在默认值的 1/10 到 10 倍之间（超出时须由 super_admin 确认并填写原因）；并满足 §16.2 末段与 §17.3 的跨字段关系。

所有保护阈值在后台有单位、范围、当前值和修改原因；不直接通过前端提交新阈值。首版 UI 不承诺“无限量”，达到业务保护线显示真实原因和恢复时间。

## 17. 运营后台与维护流程

### 17.1 页面与权限

| 页面 | 内容 | 权限 |
| --- | --- | --- |

| 错误记录 | traceId、阶段、平台、适配器版本、错误码、耗时 | 技术管理员；默认不展示原链接 |
| 反馈工单 | 筛选、详情、状态、回复 | 客服/运营；敏感附加信息按需授权 |

表中角色与 §14.13 的角色枚举对应：查看者 = viewer，运营 = operator，技术管理员 = tech_admin，客服 = support，审计角色 = auditor，管理员 = super_admin。首版可由同一人承担多个角色，但后端权限判断仍保留。Cookie/密钥配置显示“已配置/未配置/版本/更新时间”，不默认回显原值。

### 17.2 平台故障

告警 → 查看错误分布和版本 → 用自有或获授权固定样本复现 → 判断源站变化、凭证、网络或媒体格式 → 暂停受影响能力 → 修复适配器 → 在测试环境验证 → 少量流量开放 → 观察后全面恢复。

平台维护不删除历史，用户重新解析时说明暂不可用。已准备好的本地缓存原则上可继续下载；若是内容撤销、访问授权变化等原因，应撤销相关资源，不能简单继续提供旧缓存。

### 17.3 配置发布

配置先校验再发布：范围、单位、跨字段关系必须成立。例如 result TTL 必须足够覆盖准备与下载窗口；票据 TTL 不能被误设为超过底层对象寿命；流量单位不能混淆。

使用 expectedVersion 乐观锁，冲突返回 409，要求重新读取。每次保存附原因并产生审计，发布后公共 configVersion 改变。回滚发布新版本，不覆盖历史审计。

| 指标 | 明确定义 |
| --- | --- |
| 解析成功率 | SUCCEEDED /（SUCCEEDED + FAILED）；取消单独列出 |

### 18.4 告警

P0 告警：来源错误显著增加、任务排队到截止、服务端出站接近保护线、磁盘高水位、清理任务超期、共享文件（media_file）无有效授权引用却长期残留、管理员登录或签票据异常、某平台未登记主机占比或直连回退率显著上升（提示补登记下载域名）。

告警样本量、窗口和阈值记录在配置；低样本不宣称平台不可用。人工维护和自动熔断分开显示，自动恢复不得覆盖管理员设置的维护状态。

## 19. 部署、资源与数据保护

### 19.1 部署组成

| 组件 | 部署要求 |
| --- | --- |
| HTTPS 入口 | 有效证书；API 域名配置为 request 合法域名，自有中转媒体域名和已登记的平台 CDN 主机配置为 downloadFile 合法域名（§13.7） |
| 业务服务 | Go 单一可执行文件：会话、任务、解析（内置解析库）、批次、反馈和管理模块，并提供嵌入的管理端页面；各模块用有界 worker 和连接数隔离 |
| 媒体工作模块 | 位于业务服务内，独立并发限额和受控目录。媒体探测调用 ffprobe 外部进程（参数数组调用，不经 shell）；WebP 转换用 Go 图片库在进程内完成，解码前先读尺寸并按 `max_image_pixels` 拒绝。首版不做音视频合并 |
| 管理端 | 由业务服务以独立路径或独立域名提供，只调用 `/admin/v1`；建议限制访问来源，不与小程序域名混用 |
| MySQL | 状态与业务数据；备份、迁移、最小权限账号 |
| 进程内短期状态（不部署 Redis） | 首版单实例：会话缓存、解析缓存、限流、熔断、租约、票据撤销在进程内存并有上限；会话和每日额度持久化到 MySQL（§15.6）。多实例部署前必须引入共享存储（P1） |
| 临时媒体存储 | 专用目录/卷，明确配额、清理和权限；后续可迁移对象存储 |

环境分为 local/test/prod，应用 ID、域名、数据库和密钥分离。Nginx 等入口的请求体和超时配置需与业务预算一致；媒体传输超时和普通 JSON 接口分别设置。数据库不直接暴露给小程序或公网。

不把“开发工具关闭域名校验后能用”当作验收。生产包、真机、真实 HTTPS 证书和已配置域名必须联测。

### 19.2 容量估算

建议按实测选择机器，不把某个 CPU/内存配置当作可承诺并发。解析主要受上游速度影响；媒体准备、转换、存储和带宽分别计量。

示例预算（假设，不是实际账单）：每天 1000 次完整视频下载、平均 20 MiB，30 天约 586 GiB 出站；尚未计预览、缩略图、重复下载和失败重试。单个 100 MiB 文件在独占 10 Mbps 链路上的理论传输时间约 84 秒，并发和协议开销会继续增加。

首版参考机型 2 核 2 GB、50 GB SSD（MySQL 同机），需配合以下设置：MySQL 关闭 performance_schema、`innodb_buffer_pool_size` 设为 256 MB；配置 2 GB swap 作为兜底；图片转换并发 `image_convert_workers` 为 1（`max_image_pixels` 解码后约 160 MB/张）。内存估算：系统 0.3–0.4 GB、MySQL 约 0.3–0.4 GB、业务服务平时 0.05–0.2 GB，图片转换高峰再加约 0.2 GB，合计约 1–1.3 GB。视频文件以流式读写磁盘，不整体载入内存。磁盘：系统与程序约 10 GB、MySQL 数 GB、`media_cache_budget_bytes` 5 GiB，50 GB 足够。解析与下载以等待网络为主，2 核 CPU 足够。用户量增长后优先升级带宽和内存，再考虑 4 核 4 GB。

因此应先测试实际吞吐，再调整大小限制和超时。成本公式：计算资源 + 源取回费用（若有）+ 存储占用 + 出站/CDN 字节 + 请求次数 + 日志/备份。缓存只减少重复源取回，不会消除到用户的出站流量。首版以直连下载为主（§13.7），出站流量主要来自中转项和预览，服务器带宽按中转量而不是总下载量估算。

### 19.3 与本项目直接相关的安全要求

- SSRF：输入和每次重定向验证域名与实际连接 IP，拒绝回环、私网、链路本地、云元数据等地址；IPv4/IPv6 均检查。解析 DNS 后建立连接还需防止重新解析落到内网。
- 文件源授权：只下载适配器登记的资源，下载接口只接 ID；客户端不得任意指定源 URL、Referer、Cookie 或文件路径。
- 凭证：AppSecret、平台 Cookie 和票据签名密钥使用环境密钥/密钥服务；普通配置与日志不保存原值；按版本轮换。
- TLS：恢复并验证证书校验，不把关闭校验当作长期网络修复方案。
- 文件：校验 MIME、魔数、实际容器、长度和解码资源消耗；文件名随机化，禁止路径穿越和脚本执行。
- 权限：普通用户对象查询都验证归属；后台独立认证；媒体短期能力票据可撤销且有流量/并发边界。
- 内容展示：用户/平台文本只作文本渲染；反馈和帮助不接受任意可执行 HTML。
- 日志：请求体与签名 query 默认不记录；必要调试使用隔离、限时、脱敏记录，不把全部线上请求永久归档。

### 19.5 发布和回滚

### 20.7 性能与可靠性门槛

- 每一个准备开放的“平台 × 内容类型”至少验证 20 个正常、可授权使用的样本，覆盖横竖视频/多图/长文案/短链接等实际形态。
- 在受控网络与已允许相册权限条件下，正常样本首次完整保存目标至少 95%；失败必须分类。未达到目标的能力不默认开放，调整阈值需有产品决策记录。
- 所有安全、越权、数据丢失、错误成功提示相关 P0 用例必须通过；不能用总体成功率抵消这些失败。
- 用至少 20 个并发用户的混合任务做一次小规模压测，记录环境、上游情况和出站带宽；过载时有界拒绝或排队，不发生 OOM、无限任务或永久占满线程。
- 解析任务遵守总截止时间；客户端最多等待配置上限。大文件实际耗时单独记录，不承诺所有网络下固定秒数完成。
- 清理任务、服务重启和平台故障演练各至少一次；真实生产指标仍需灰度观测，不能用测试样本推算长期平台成功率。

| qushuiyin_service/internal/auth | 微信 code 交换、业务会话和对象授权 |
| qushuiyin_service/internal/parse | 链接识别、任务、缓存、平台适配器；唯一引用 parse-video 解析库的位置 |
| qushuiyin_service/internal/media | 文件准备、签票据、配额、输出与清理 |
| qushuiyin_service/internal/feedback | 工单、回复、联系方式保护 |
| qushuiyin_service/internal/admin | 权限、配置、概览、审计 |
| qushuiyin_service/web/admin | 管理端前端源码（Vue 3 + Element Plus）：登录、平台状态、配置发布、下载域名、错误检索、反馈处理、审计、管理员账号。构建输出到 `qushuiyin_service/internal/admin/dist` 并用 go:embed 嵌入（go:embed 只能引用本包目录及子目录，所以前端不能放在服务目录之外） |
| deploy | 环境模板、容器编排、迁移、健康检查、回滚说明 |

后端模块位于同一 Go 工程。工程规范（Go 版本与依赖库、迁移、配置、本地开发与 Mock、仓库结构、执行顺序与人工步骤）见《03-去水印小程序-开发执行说明.md》。真正的大文件流传输由有界媒体处理能力承担，goroutine 与连接数都要有上限，不能无限占用普通接口的处理能力。

### 21.2 每个工作包的交付标准

1. 功能代码和实际接口契约一致，枚举、单位、字段可空性一致。
2. 有正常与关键失败样例；不同平台适配器至少有最小契约验证。
3. 更新环境变量模板但不提交真实密钥。
4. 数据库变更提供迁移和兼容说明，不手工改生产表后遗忘记录。
5. 相应验收编号有通过/失败/未测结论和依据。
6. 未实现的能力在配置里关闭，不能只隐藏按钮而后端仍无保护。

### 21.3 推荐里程碑

M0：确定解析器真实能力和真机下载链路。  
M1：模型、配置、会话、Mock、任务骨架。  
M2：至少一个平台的视频完整闭环，然后扩展已验证平台。  
M3：图集、格式转换、部分失败恢复。  
M4：历史、帮助、反馈、隐私、最小运营后台。  
M5：性能、故障恢复、域名权限、发布和回滚。

具体任务 T01—T17 和依赖见《功能大纲与开发路线》第 7 章。先完成一条真实保存链路，再铺开页面和平台；不要等所有页面完成后才验证媒体域名与相册保存。

### 21.4 发布说明模板内容

每次发布记录：版本号、开放平台和类型、新增/调整行为、已知限制、默认参数变更、数据库迁移、验证设备/网络、失败样本和处理方式、回滚版本。
